# 길픽 요구사항 정의서

## 1. 범위와 원칙

- 여행, 날짜별 일정, 경로, 진행 상태는 여행 단위로 분리한다.
- 기준 시간대는 `Asia/Seoul`이다.
- 자동 감지가 불가능해도 수동 도착·출발·상태 수정으로 여행을 진행할 수 있다.
- 외부 데이터가 누락되면 해당 변수만 제외하며, 다른 기능까지 실패시키지 않는다. 경로 제공자 실패는 경로 계산 실패로 처리한다.

## 2. 기능 요구사항

| ID | 분류 | 기능 | 요구사항 |
|---|---|---|---|
| AUTH-01 | 인증 | 카카오 로그인 | 백엔드는 기기별 로그인 transaction을 만들고 HTTPS callback으로 카카오 인가 코드를 받아 사용자 검증을 수행한다. 앱은 verified App Link로 받은 일회용 login ticket을 교환해 길픽 Token을 발급받는다. |
| AUTH-02 | 인증 | 세션 관리 | Access Token은 1시간 유효하다. Refresh Token은 최초 로그인과 각 회전 발급 시점부터 30일 유효하며 MVP에는 별도 절대 만료 상한을 두지 않는다. 다중 기기를 허용하고 로그아웃 시 현재 기기의 Refresh Token만 폐기한다. 만료·폐기 session은 30일 후 삭제한다. |
| TRIP-01 | 여행 | 여행 생성 | 여행명은 2~30자이며 중복을 허용한다. 여행 기간은 최대 7일이다. |
| TRIP-02 | 여행 | 여행 목록 | 여행명 검색, 상태 필터, 무한 스크롤을 제공한다. 여행 중·예정·완료 그룹 순으로 정렬한다. |
| TRIP-03 | 여행 | 여행 상태 | KST 현재 날짜가 시작일 전이면 예정, 기간 내이면 여행 중, 종료일 후이면 완료다. |
| TRIP-04 | 여행 | 여행 기간 수정 | 기간 축소로 삭제될 일정 수를 안내하고 사용자 확인 후 범위 밖 일정을 삭제한다. |
| TRIP-05 | 여행 | 여행 삭제 | 논리 삭제하며 일반 조회에서 제외한다. MVP에서는 복구와 자동 물리 삭제를 제공하지 않는다. |
| PLACE-01 | 장소 | 장소 검색·상세 | TourAPI를 실시간 호출하고 일정 저장에 필요한 최소 참조정보만 보관한다. |
| ITIN-01 | 일정 | 날짜별 일정 | 장소, 순서, 체류시간, 이동수단을 저장하고 지도에 경로를 표시한다. |
| ITIN-02 | 일정 | 체류시간 | 카테고리 추천값을 자동 입력하고 30분 단위로 조절한다. 허용 범위는 30~360분이다. |
| ITIN-03 | 일정 | 일정 수정 | 미처리 장소는 장소·순서·체류시간·이동수단을 수정한다. 처리된 장소는 상태·체류시간·순서를 수정한다. 장소 교체 시 기존 상태를 유지한다. |
| ROUTE-01 | 경로 | 경로 계산 | 도보·자동차는 TMAP, 대중교통은 ODsay를 사용하고 10초 안에 동기 응답한다. |
| ROUTE-02 | 경로 | 계산 실패 | 일정 저장은 유지하고 `routeStatus: FAILED`를 반환한다. 자동 재시도 1회 후 사용자가 다시 계산할 수 있다. |
| PROG-01 | 진행 | 여행 시작 | 버튼 요청을 받은 서버 시각을 최초 한 번만 `actualStartedAt`으로 저장하고 전체 ETA와 변수 감지를 시작한다. |
| PROG-02 | 진행 | ETA | 현재 위치가 있으면 첫 장소의 기준점으로 사용한다. 이후 ETA는 이전 장소 도착시각, 계획 체류시간, 다음 구간 이동시간으로 계산한다. |
| PROG-03 | 진행 | 상태 | 기본 상태는 `PLANNED → EN_ROUTE → ARRIVED → COMPLETED`이며 어떤 상태에서도 `SKIPPED`로 변경할 수 있다. 완료·건너뛰기 취소와 수동 상태 수정을 허용한다. |
| PROG-04 | 진행 | 자동 도착 | 다음 장소 300m 이내 5분 DWELL 후 확인한다. 5분 무응답이면 자동 도착 처리하고 5분간 되돌리기를 제공한다. |
| PROG-05 | 진행 | 도착 재알림 | `아직이에요` 선택 시 10분 뒤 한 번만 다시 알린다. 최초 알림을 포함해 장소별 최대 2회다. |
| PROG-06 | 진행 | 수동 출발 | `다음 장소로 출발` 버튼은 즉시 현재 장소 완료와 다음 장소 이동 시작을 확정한다. 별도 즉시 되돌리기는 제공하지 않으며 일반 상태 수정은 가능하다. |
| PROG-07 | 진행 | 자동 출발 | 현재 장소 400m 밖 EXIT 후 확인한다. 5분간 무응답이고 재진입하지 않으면 자동 출발 처리하고 5분간 되돌리기를 제공한다. |
| PROG-08 | 진행 | 출발 오판 | `아직 머무는 중` 선택 시 해당 장소의 자동 출발 감지를 중단하고 수동 출발만 허용한다. |
| PROG-09 | 진행 | 가까운 장소 | 이전 장소 EXIT 없이 바로 다음 장소 DWELL이 발생하면 이전 완료와 다음 도착을 원자적으로 처리한다. |
| PROG-10 | 진행 | 수동 도착 수정 | 장소를 수동으로 `ARRIVED`로 바꾸면 이후 장소를 `PLANNED`로 초기화하고 ETA와 변수 감지를 재계산한다. |
| PROG-11 | 진행 | 마지막 장소 | 마지막 장소 도착 확정 시 당일 일정을 완료하고 ETA·경로 재계산·변수 감지·알림·지오펜스를 종료한다. 되돌리면 함께 복구한다. |
| LOC-01 | 위치 | 이벤트 검증 | 위치 정확도 100m 이하, 발생 후 2분 이내 이벤트를 자동 감지에 사용하며 실제 테스트로 조정할 수 있다. |
| LOC-02 | 위치 | 권한·실패 대응 | 정밀 또는 백그라운드 위치를 사용할 수 없으면 해당 자동 감지만 비활성화하고 계획 경로 ETA와 수동 진행을 제공한다. |
| DET-01 | 감지 | 실행 주기 | 진행 중인 남은 일정을 10분마다 평가한다. 동일 장소에 제안 후 사용자 결정 전까지 중복 알림을 보내지 않는다. |
| DET-02 | 혼잡 | 지원지역 | 장소 500m 이내 서울시 혼잡 지원 장소가 있으면 같은 영향을 적용한다. ETA 갱신 시 혼잡 데이터도 갱신한다. |

## 3. 데이터 누락과 외부 API 실패

| 대상 | 제한 | 최종 실패 처리 |
|---|---|---|
| TourAPI | 5초, 1회 재시도 | 해당 관광 데이터만 제외 |
| TMAP·ODsay | 각각 5초, 1회 재시도 | 경로 계산 실패 |
| Google Places | 5초, 1회 재시도 | Google 기반 평점·운영정보 변수 제외 |
| 기상청 | 5초, 1회 재시도 | 날씨 변수 제외 |
| 서울시 데이터 | 5초, 1회 재시도 | 혼잡 변수 제외 |

평점은 베이지안 보정을 사용한다. `보정 평점=(v/(v+m))×R+(m/(v+m))×C`이며, `R`은 장소 평점, `v`는 리뷰 수, `C`는 후보 평균 평점, `m`은 후보 리뷰 수 중앙값이다. 후보가 5개 미만이면 `m=20`을 사용한다. 화면 점수만 정수로 반올림하고 정렬에는 원점수를 사용한다.

## 4. 비기능 요구사항

- 모든 보호 API는 사용자와 여행 소유권을 검증한다.
- 수정 API는 일정 버전 충돌과 중복 이벤트를 방지한다.
- ID는 UUID, API 기본 경로는 `/api/v1`, 목록은 cursor 페이지네이션을 사용한다.
- 성공·오류 응답은 공통 envelope를 사용한다.
- 앱 토큰은 Android Keystore 기반 안전 저장소에 보관한다.
- 위치 이벤트와 상태 변경에는 발생 시각, 처리 출처, 변경 전후 상태를 기록한다.
