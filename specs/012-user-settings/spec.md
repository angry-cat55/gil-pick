## User Scenarios & Testing *(mandatory)*

### User Story 1 - 장소 변경 제안 알림을 통제한다 (Priority: P1)

로그인한 사용자는 설정 화면에서 장소 변경 제안 알림의 현재 상태를 확인하고 켜거나 끌 수 있다. 변경한 값은 앱을 다시 열거나 다른 기기에서 같은 계정으로 접속해도 유지된다.

**Why this priority**: 사용자가 불필요한 제안 알림을 직접 통제하게 하는 것이 F012의 핵심 가치이며, F011이 알림을 생성할 때 참조할 사용자 선택을 제공한다.

**Independent Test**: 알림 설정을 끈 뒤 설정 화면을 다시 열어 꺼짐 상태가 유지되는지 확인하고, 이후 발생한 장소 변경 제안 알림은 생성되지 않지만 도착·출발 확인 알림은 계속 동작하는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 처음 설정을 확인하는 사용자의 장소 변경 제안 알림이 기본으로 켜져 있고, **When** 설정 화면을 열면, **Then** 저장된 현재 상태가 켜짐으로 표시된다.
2. **Given** 장소 변경 제안 알림이 켜져 있고, **When** 사용자가 설정을 끄면, **Then** 변경 완료가 화면에 명확히 표시되고 이후 새 장소 변경 제안 알림부터 생성·전달이 중단된다.
3. **Given** 장소 변경 제안 알림이 꺼져 있고, **When** 사용자가 설정을 다시 켜면, **Then** 이후 새 감지 결과부터 장소 변경 제안 알림이 재개되고 꺼진 동안 건너뛴 알림은 소급 생성·전달되지 않는다.
4. **Given** 사용자가 설정을 변경했고, **When** 설정 화면을 나갔다가 다시 열거나 다른 로그인 기기에서 확인하면, **Then** 마지막으로 저장된 상태가 동일하게 표시된다.
5. **Given** 설정 변경을 저장할 수 없는 오류가 발생했고, **When** 사용자가 토글을 조작하면, **Then** 화면은 저장에 성공한 이전 상태로 돌아가고 실패 이유와 다시 시도할 방법을 제공한다.
6. **Given** 장소 변경 제안 알림을 꺼 두었고, **When** 도착·출발 확인 알림 조건이 충족되면, **Then** 여행 진행에 필요한 도착·출발 확인 알림은 설정과 무관하게 계속 동작한다.
7. **Given** 같은 계정의 두 기기가 거의 동시에 서로 다른 값을 저장한다, **When** 두 요청이 모두 성공하면, **Then** 서버가 마지막으로 성공 처리한 값이 계정의 최종 상태가 되고 두 기기는 다음 조회에서 같은 값을 표시한다.

### User Story 2 - 정책 문서를 확인한다 (Priority: P2)

로그인한 사용자는 설정 화면에서 현재 적용되는 개인정보처리방침과 이용약관을 각각 앱 내 브라우저 화면으로 열어 읽고 설정 화면으로 돌아올 수 있다.

**Why this priority**: 사용자가 서비스 이용과 개인정보 처리 기준을 언제든 확인할 수 있어야 신뢰와 정책 투명성을 확보할 수 있다.

**Independent Test**: 두 정책 진입점을 각각 선택했을 때 승인된 최신 문서가 구분되어 열리고, 읽은 뒤 기존 설정 화면으로 돌아올 수 있는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 설정 화면의 content 상태이고, **When** 사용자가 개인정보처리방침을 선택하면, **Then** 승인된 HTTPS 위치의 현재 개인정보처리방침이 앱 내 브라우저 화면에서 열린다.
2. **Given** 설정 화면의 content 상태이고, **When** 사용자가 이용약관을 선택하면, **Then** 승인된 HTTPS 위치의 현재 이용약관이 앱 내 브라우저 화면에서 열린다.
3. **Given** 사용자가 정책 문서를 열었다, **When** 뒤로 이동하면, **Then** 로그아웃되거나 설정 값을 잃지 않고 설정 화면으로 돌아온다.
4. **Given** 정책 URL이 비어 있거나 HTTPS가 아니거나 Custom Tab을 실행할 수 없고, **When** 사용자가 문서 진입점을 선택하면, **Then** 현재 화면을 유지하면서 실패 이유와 다시 시도할 방법을 제공한다.

---

### User Story 3 - 현재 기기에서 로그아웃한다 (Priority: P2)

로그인한 사용자는 설정 화면에서 현재 기기의 로그인 상태를 즉시 종료하고 로그인 화면으로 이동할 수 있다. 같은 계정으로 로그인한 다른 기기의 상태는 유지된다.

**Why this priority**: 공용·분실 가능성이 있는 기기에서 사용자가 자신의 접근 권한을 즉시 통제할 수 있어야 한다. 로그아웃 처리 규칙 자체는 F001이 이미 확정했다.

**Independent Test**: 같은 계정으로 두 기기에 로그인한 뒤 설정 화면에서 한 기기만 로그아웃하여 현재 기기는 로그인 화면으로 이동하고 다른 기기는 계속 이용 가능한지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 설정 화면에 로그인 상태로 있다, **When** 로그아웃을 선택하면, **Then** 현재 기기의 로컬 로그인 상태가 즉시 종료되고 로그인 화면으로 이동한다.
2. **Given** 같은 계정이 여러 기기에 로그인되어 있다, **When** 현재 기기에서 로그아웃하면, **Then** 다른 기기의 로그인 상태는 변경되지 않는다.
3. **Given** 네트워크 단절이나 서버 오류가 발생했다, **When** 사용자가 로그아웃하면, **Then** 현재 기기의 로컬 로그아웃과 로그인 화면 이동은 완료되고 서버의 현재 기기 자격 폐기는 F001의 재시도 규칙을 따른다.

---

### User Story 4 - 계정과 앱 정보를 확인한다 (Priority: P3)

로그인한 사용자는 설정 화면에서 현재 카카오 연동 계정의 표시 정보와 설치된 앱 버전을 확인할 수 있다.

**Why this priority**: 사용자가 어떤 계정으로 접속했는지 확인하고 문의·문제 해결 시 앱 버전을 식별할 수 있게 하지만, 알림 통제와 정책·로그아웃보다 우선순위는 낮다.

**Independent Test**: 로그인 세션에 있는 닉네임·프로필 이미지 유무별 표시와 카카오 연동 상태, 설치된 앱 버전 표시를 각각 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인 세션에 닉네임과 프로필 이미지가 있다, **When** 설정 화면을 열면, **Then** 해당 표시 정보와 카카오 연동 상태가 나타난다.
2. **Given** 닉네임 또는 프로필 이미지가 없다, **When** 설정 화면을 열면, **Then** 누락 값을 지어내지 않고 대체 표시를 사용하며 설정 기능은 계속 이용할 수 있다.
3. **Given** 설정 화면의 content 상태이다, **When** 앱 정보 영역을 확인하면, **Then** 현재 설치된 앱 버전을 식별할 수 있다.

### Edge Cases

- 설정 화면을 처음 여는 중 조회가 1초를 넘으면 설정 영역에 대기 상태를 표시하되 정책 문서와 로그아웃 진입은 불필요하게 차단하지 않는다.
- 설정 조회에 실패하면 저장되지 않은 기본값을 현재 값처럼 표시하지 않고, 마지막으로 확인된 값이 있으면 그 값임을 유지하면서 재시도 경로를 제공한다. 확인된 값이 없으면 토글 변경을 막고 재시도를 제공한다.
- 사용자가 토글을 빠르게 여러 번 조작해도 최종적으로 성공한 마지막 요청의 값과 화면 상태가 일치해야 하며, 이전 요청의 늦은 응답이 최신 선택을 덮어쓰면 안 된다.
- 같은 계정의 여러 기기에서 서로 다른 값을 거의 동시에 변경하면 서버가 마지막으로 성공 처리한 값을 최종 상태로 사용하고, 각 기기는 다음 조회에서 그 값을 반영한다.
- 설정 변경 결과를 확인하기 전에 인증이 만료되면 임의로 성공 처리하지 않고 F001의 로그인 상태 갱신·재로그인 규칙을 따른다.
- 정책 문서 위치가 비어 있거나 HTTPS가 아니거나 Custom Tab을 실행할 수 없어도 앱 전체가 종료되거나 로그아웃되어서는 안 된다. Custom Tab 실행 뒤의 네트워크·HTTP·문서 로딩 오류는 앱이 관찰할 수 없으므로 브라우저가 표시한다.
- 로그아웃을 연속해서 여러 번 요청해도 현재 기기 외의 세션이나 사용자 설정을 변경하지 않는다.
- 시스템 글자 크기를 최대로 키우거나 화면을 회전해도 설정 이름, 현재 상태, 정책 문서와 로그아웃 진입점이 잘리거나 겹치지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 F012의 사용자 변경 가능 설정으로 장소 변경 제안 알림 전체 ON/OFF 하나만 제공해야 한다. 혼잡도·강수 예보·운영 종료별 개별 토글, 감지 기준·변수 가중치 조절과 설정 초기화는 제공하지 않아야 한다.
- **FR-002**: 시스템은 인증된 사용자의 저장된 알림 설정을 조회해 현재 상태로 표시해야 하며, 새 사용자의 장소 변경 제안 알림 설정 기본값은 켜짐이어야 한다.
- **FR-003**: 사용자는 제공되는 알림 설정을 변경할 수 있어야 하고, 성공한 변경은 앱 재실행과 같은 계정의 다른 로그인 기기에서도 일관되게 조회되어야 한다. 여러 기기의 서로 다른 변경이 겹치면 서버가 마지막으로 성공 처리한 값을 최종 상태로 사용해야 한다.
- **FR-004**: 장소 변경 제안 알림 설정 변경은 이후 새로 생성되는 알림부터 적용해야 하며, 꺼진 동안 건너뛴 알림을 다시 켰을 때 소급 생성·전달해서는 안 된다.
- **FR-005**: 장소 변경 제안 알림 설정은 도착·출발 확인 알림과 감지 결과 자체의 생성·조회에 영향을 주어서는 안 된다.
- **FR-006**: 설정 조회·변경 실패를 성공처럼 표시해서는 안 되며, 변경 실패 시 마지막으로 저장에 성공한 상태를 유지하고 사용자가 다시 시도할 수 있게 해야 한다.
- **FR-007**: 사용자는 설정 화면에서 개인정보처리방침과 이용약관을 구분하여 선택하고, 승인된 HTTPS 위치의 현재 문서를 앱 내 브라우저 화면으로 읽은 뒤 설정 화면으로 돌아올 수 있어야 한다. 별도의 정책 전용 앱 화면이나 앱에 포함된 정책 문서를 제공하지 않아야 한다.
- **FR-008**: 정책 URL이 비어 있거나 HTTPS가 아니거나 Custom Tab을 실행할 수 없는 경우 시스템은 설정 화면과 로그인 상태를 유지하고 실패 이유와 다시 시도할 방법을 제공해야 한다. Custom Tab 실행 뒤의 네트워크·HTTP·문서 로딩 오류 표시는 브라우저에 맡긴다.
- **FR-009**: 설정 화면은 현재 로그인 세션에서 확인된 닉네임·프로필 이미지·카카오 연동 상태와 현재 설치된 앱 버전을 표시해야 한다. 제공되지 않은 계정 정보는 지어내지 않고 대체 표시를 사용해야 한다.
- **FR-010**: 설정 화면의 로그아웃 진입은 F001이 확정한 현재 기기 로그아웃을 실행해야 한다. 로컬 로그인 상태는 네트워크와 관계없이 즉시 종료하고 다른 기기의 로그인 상태는 유지해야 한다.
- **FR-011**: 설정 조회·변경과 계정 정보 표시는 인증된 현재 사용자에게만 허용해야 하며 다른 사용자의 설정이나 계정 정보를 조회·변경할 수 없어야 한다.
- **FR-012**: 시스템은 설정 조회·변경 결과를 요청 단위로 추적할 수 있어야 하되 로그인 자격, 정책 문서 접근 정보 또는 불필요한 개인정보를 추적 정보에 포함해서는 안 된다.
- **FR-013**: F012는 설정 화면과 사용자 설정 조회·변경, 정책 문서 진입, 기존 현재 기기 로그아웃 연결까지만 책임진다. 계정 탈퇴, 프로필 수정, 카카오 연결 해제, 모든 기기 일괄 로그아웃은 포함하지 않는다.

### UI Requirements *(include if feature contains user-facing UI)*

- **UI-001**: 설정 화면의 항목, 순서, 문구, 계정 정보, 앱 정보, 정책 문서와 로그아웃 진입의 시각적 구성은 Figma Make `SettingsScreen`을 정본으로 검증한다. 현재 Figma의 변수별 토글·감지 기준·설정 초기화는 FR-001의 확정 범위와 충돌하므로 구현 전에 Figma 원본과 저장소 사본에서 제거하고, 장소 변경 제안 알림 전체 ON/OFF 하나만 남긴 승인본을 시각 검증 기준으로 사용해야 한다.
- **UI-002**: 설정 화면은 앱의 최상위 설정 탭에서 진입할 수 있어야 하며, 다른 최상위 화면을 다녀와 돌아왔을 때 마지막으로 저장에 성공한 설정 상태를 일관되게 표시해야 한다.
- **UI-003**: `content` 상태에서는 저장된 설정과 계정·앱·정책 정보를 제공한다. 초기 설정 조회가 1초를 넘으면 해당 설정 영역에 `loading`을 표시하고, 조회·변경 실패 시 원인과 재시도 행동이 있는 `error` 상태를 제공한다. 인증된 사용자에게 항상 설정 값이 존재하므로 `empty` 상태는 적용하지 않는다.
- **UI-004**: 설정 갱신 중에도 정책 문서와 로그아웃처럼 독립적으로 수행 가능한 행동은 계속 사용할 수 있어야 하며, 토글은 중복 요청을 방지하면서 처리 중임을 시각적으로 알려야 한다.
- **UI-005**: 모든 터치 대상은 최소 48×48dp와 대상 간 8dp 간격을 확보하고, 토글 상태와 오류는 색만으로 전달하지 않아야 한다. 아이콘 전용 컨트롤은 식별 가능한 설명을 가지며, 시스템 글자 확대에서도 핵심 문구와 상태가 잘리지 않아야 한다.
- **UI-006**: 360dp 너비의 작은 화면에서 가로 스크롤이나 잘림이 없어야 하고, phone·tablet의 세로·가로 방향에서 정책 문서와 로그아웃을 포함한 모든 항목에 스크롤로 접근할 수 있어야 한다. 고정된 하단 탐색이나 시스템 영역이 내용을 가려서는 안 된다.
- **UI-007**: 설정 화면은 구현 후 Figma 정본과 screenshot으로 비교하고, `loading`·`error`·`content`, 설정 변경 성공·실패, 정책 문서 진입·복귀, 로그아웃 이동을 실제 기기 또는 동등한 실행 환경에서 검증해야 한다.

### Key Entities *(include if feature involves data)*

- **사용자 설정**: 인증된 사용자 계정에 하나만 귀속되는 장소 변경 제안 알림 허용 여부이며 기본값은 켜짐이다. 여러 기기의 변경에는 마지막으로 성공 처리된 값이 남고, 변수별 감지 기준이나 가중치는 포함하지 않는다.
- **사용자 표시 정보**: 현재 로그인 계정을 식별하기 위한 선택적 닉네임과 프로필 이미지, 카카오 연동 상태다. 인증 기능이 제공한 값을 읽기 전용으로 사용한다.
- **정책 문서**: 사용자가 설정 화면에서 접근하는 승인된 현재 개인정보처리방침과 이용약관이다. 각 문서의 식별 가능한 제목과 접근 위치를 가진다.
- **앱 정보**: 사용자가 현재 설치본을 식별할 수 있는 앱 버전이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대표 Android 기기 또는 emulator에서 설정 화면 진입부터 알림 설정 변경 완료 확인까지의 수동 검증 5회가 모두 30초 이내에 끝난다.
- **SC-002**: 두 client가 서로 다른 값으로 동시에 설정을 변경한 뒤 재조회하는 자동 검증 10회에서 서버가 마지막으로 성공 처리한 값과 각 client에 다시 표시되는 값이 모두 일치한다.
- **SC-003**: 장소 변경 제안 알림을 끈 검증 시나리오의 100%에서 이후 제안 알림이 생성·전달되지 않고, 도착·출발 확인 알림과 감지 결과 생성은 계속 동작한다.
- **SC-004**: 설정 조회·변경 실패와 늦은 응답을 포함한 검증 시나리오의 100%에서 저장되지 않은 값을 성공 상태로 남기거나 이전 응답이 최신 선택을 덮어쓰는 사례가 0건이다.
- **SC-005**: 정상 네트워크의 대표 Android 기기 또는 emulator에서 개인정보처리방침과 이용약관을 각각 5회 연 수동 검증이 모두 선택 후 3초 이내에 올바른 문서를 표시한다. 빈 URL·HTTP URL·Custom Tab 실행 불가 자동 검증은 모두 설정 화면과 로그인 상태를 유지하고 재시도 방법을 제공한다.
- **SC-006**: 두 기기에 로그인한 계정의 현재 기기 로그아웃 검증 시나리오 100%에서 현재 기기는 즉시 로그인 화면으로 이동하고 다른 기기의 로그인 상태는 유지된다.
- **SC-007**: 360dp 화면, phone·tablet의 세로·가로 방향, 시스템 최대 글자 크기 검증에서 핵심 설정과 정책·로그아웃 진입점의 가로 잘림·겹침·접근 불가 사례가 0건이다.
- **SC-008**: 구현 담당자를 제외한 팀원 2명이 별도 설명 없이 현재 알림 설정 상태, 정책 문서 위치, 로그아웃 위치를 각각 첫 시도에 찾는다. 두 명을 확보하지 못하면 미검증으로 기록하고 완료로 간주하지 않는다.

## Assumptions

- F012의 사용자는 카카오 인증을 완료한 Android 앱 사용자이며, F001이 제공하는 로그인 세션과 현재 기기 로그아웃 규칙을 재사용한다.
- 현재 승인된 MVP 문서와 사용자 설정 계약에 따라 장소 변경 제안 알림 전체 ON/OFF 하나와 기본값 켜짐을 사용한다. 변수별 감지 기준과 가중치는 공통 정책값으로 유지하며 사용자별 설정으로 노출하지 않는다.
- 닉네임과 프로필 이미지는 현재 로그인 세션에 보관된 값을 사용하며, 별도의 프로필 조회·수정 기능을 F012에 추가하지 않는다.
- MVP 인증 provider는 카카오 하나뿐이므로 F001의 인증된 session이 존재하면 카카오 연동 상태로 표시한다. F012를 위해 session에 provider field나 별도 계정 조회 API를 추가하지 않는다.
- 정책 문서의 승인된 내용과 HTTPS 접근 위치는 구현 시작 전에 제품·운영 담당자가 제공한다. 별도의 정책 전용 앱 화면, 앱에 포함된 오프라인 문서, 정책 편집·버전 관리 기능은 F012에 포함하지 않는다.
- 로그아웃은 Figma와 F001의 기존 흐름대로 별도 확인 단계 없이 즉시 실행한다. 계정 삭제가 아니며 사용자는 다시 로그인할 수 있다.
- F011 구현 완료 전에도 F012는 설정 값을 조회·변경할 수 있어야 한다. 설정이 실제 장소 변경 제안 알림 생성에 반영되는 종단간 검증은 F011의 설정 존중 동작에 의존한다.

## Dependencies

- **F001 인증(DONE)**: 로그인 세션, 카카오 사용자 표시 정보, 현재 기기 로그아웃과 실패 시 서버 자격 폐기 재시도 규칙을 재사용한다.
- **F011 알림(IN_PROGRESS)**: F012가 저장한 장소 변경 제안 알림 설정을 발송 시 읽어 존중해야 한다. F012의 설정 저장 자체는 F011 없이 독립적으로 동작해야 한다.
- **정책 문서 제공**: 승인된 현재 개인정보처리방침과 이용약관의 내용 및 HTTPS 접근 위치가 구현·종단간 검증 전에 준비되어야 한다.
- **Figma 설정 화면 정합화**: 구현 전에 Figma 원본과 저장소 사본에서 변수별 알림 토글·감지 기준·설정 초기화를 제거하고, FR-001의 단일 장소 변경 제안 알림 설정을 반영한 승인본을 제공해야 한다.

## Out of Scope

- 계정 탈퇴, 사용자 프로필 수정, 카카오 계정 연결 해제
- 모든 기기 일괄 로그아웃과 다른 기기의 세션 관리
- 정책 문서 작성·편집·승인·버전 관리 기능
- 별도의 정책 전용 앱 화면과 앱에 포함된 오프라인 정책 문서
- 앱 전체 알림 권한 설정 또는 운영체제 알림 설정 대체
- 사용자별 혼잡·날씨·운영시간 임계값·변수 가중치 조절, 개별 변수 알림 토글과 설정 초기화
